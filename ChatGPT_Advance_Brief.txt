3. CORE SECURITY & AUTHENTICATION ARCHITECTURE
--------------------------------------------------------------------------------
The application enforces a rigorous, multi-layered Dual-Factor Authentication (2FA) security model:

A. Identification & Cross-Device Portability (No Device-Silos):
   - Accounts are indexed uniquely by verified mobile phone numbers (`profiles` table).
   - Unlike legacy apps that lock accounts to a single physical phone IMEI, users can log into their exact financial profile from any Android device.
   - When a user enters their phone number on any device, the system queries Supabase (`profiles` lookup) to confirm account existence before initiating dual-factor verification.

B. Factor 1: Hardware Biometric Enforcement (`local_auth`):
   - The app triggers the OS-level biometric prompt.
   - Fingerprint verification takes place entirely inside the device's hardware Secure Enclave / Trusted Execution Environment (TEE). No raw biometric data leaves the device or touches application memory.
   - Note on Deprecations: All previous simulated face recognition fallbacks and external Python face recognition processing servers have been EXPLICITLY REMOVED AND DEPRECATED to eliminate third-party server vulnerabilities and processing latency.

C. Factor 2: Encrypted 4-Digit Application PIN:
   - Upon confirmed hardware fingerprint verification, the user inputs their 4-digit security PIN via a secure in-app keypad.
   - Once both factors pass, the system issues a secure session token and synchronizes the user's financial balance, ledger, Safebox, and active loans in real time.

D. Forensic Cloud Security Auditing (`biometric_login_logs`):
   - Every single login attempt across any device logs an immutable record inside the Supabase `biometric_login_logs` table (capturing `user_id`, device metadata, verification method, success state, and timestamp).

5. SUPABASE DATABASE SCHEMA OVERVIEW
--------------------------------------------------------------------------------
• `profiles`: `id` (UUID, PK), `phone_number` (Unique), `full_name`, `account_number` (`210...`), `pin_code` (Hashed), `balance` (Numeric), `safebox_balance` (Numeric), `loan_balance` (Numeric), `kyc_tier` (Text), `avatar_url` (Text).
• `transactions`: `id` (UUID, PK), `user_id` (FK), `sender_account`, `recipient_account`, `amount`, `fee`, `reference` (`TXN-...`), `type` (`transfer`, `deposit`, `withdrawal`, `bill_payment`), `status`, `created_at`.
• `safebox_savings`: `id` (UUID, PK), `user_id` (FK), `title`, `target_amount`, `current_amount`, `maturity_date`, `status` (`active`, `completed`).
• `loans`: `id` (UUID, PK), `user_id` (FK), `principal_amount`, `total_repayment`, `interest_rate` (5.0), `due_date`, `status` (`active`, `paid`).
• `biometric_login_logs`: `id` (UUID, PK), `user_id` (FK), `device_info`, `login_method` (`fingerprint_pin`), `status` (`success`, `failed`), `timestamp`.
